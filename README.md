# 合理調整宣導討論平台 v3（第三區塊案例推演更新）

網站：<https://madspider02.github.io/ra-platform/>

這個版本是在前一版 **四區塊工作坊** 上修改「區塊 3｜案例推演」，不是重新製作網站。其他三個區塊、可用真名／暱稱／匿名參與、返回代碼、重新編輯，以及大家的想法和即時更新等功能維持不變。

## 一、第三區塊改成什麼？

三個案例，**每個案例可以獨立儲存及修改**：

| 項目 | 指引原案例 | 指引印刷頁碼 | 工作坊情境 |
|---|---|---|---|
| 阿哲 | 案例 4：嚴重骨折的合理調整請求 | 13–14 | 車禍骨盆骨折，復健期間需要輪椅與校內支持 |
| 德德 | 案例 2：罕見疾病環境與課程調整 | 11–12 | 粒線體缺陷影響體育課、校外教學及體育表演會 |
| 小紜 | 案例 5：重大傷病環境調整 | 14–15 | 白血病治療後返校，須兼顧感染風險與學習參與 |

情境是依《各教育階段學校及幼兒園提供合理調整參考指引》（教育部，114 年 8 月）改寫；**為了讓老師自行選擇主責單位，情境中刻意不先揭露原指引所寫的受理窗口與最後決定**。若已儲存自己的答案，可展開「參考指引中的實際處理方式」對照。

每個案例都依下列順序填寫：

1. **主責業務單位（單選）**：學務處、教務處、輔導室、總務處、其他。選「其他」後可填寫單位名稱。請教師依具體調整需求、學校組織及業務分工評估；受理窗口、主責單位及執行單位不必然相同。
2. **建議的具體調整措施**：先描述希望評估／實施的措施；如果沒有具體措施，後續四項原則也就缺少判斷對象。
3. **四項原則**：依序為「目的性」「相關性」「可行性」「比例性（不成比例或過度負擔）」。每項先選「符合／尚待釐清／不符合」，再簡述判斷依據或需補充的資訊。
4. **爭議處理**：若學生、家長與學校對調整措施有不同意見，討論如何對話、提供客觀書面理由、研議替代方案與告知申訴途徑。

*本版採用「每個原則都要有選擇和簡短理由」才可以儲存案例。* 這樣觀看公開結果時，不只看得到「符合」或「不符合」，也能理解每位老師為何如此判斷。

## 二、「大家的想法」現在會看到什麼？

針對每個案例，結果頁會分別顯示：

- 目前大家選擇的**主責單位人數分布**。
- 每一位教師公開顯示的稱呼與**擬議調整措施**。
- 四項原則的**判斷結果與理由**。
- 對**爭議處理**的回應。
- 可展開**參考指引的處理方式**供討論後對照。

同一人於同一案例再次儲存會**更新原回覆、不增加人數**；一個人可對阿哲、德德及小紜三個案例分別回答。

## 三、原有 Google Sheets 怎麼處理？

本版**沿用 v2 原本的七張 `RA_` 工作表，不新增新工作表**。後台 `setup()` 對 `RA_區塊三` 做相容性升級：

- 原先 5 欄 `updatedAt`、`participantId`、`caseId`、`approach`、`dispute` **不變**；
- 在後面新增 `leadUnit`、`leadOther`、`measures`，以及四項原則各自的 `Choice` 與 `Note`，總共增加 11 欄，成為 16 欄；
- 原有舊案例 `trip`、`lights`、`writing` 的紀錄**保留在工作表**，但因案例已經換成三個新案例，舊資料不會顯示在新版第三區塊，避免把不同案例混為一談；
- 其他區塊與過往資料不受本次案例切換影響。

請務必先備份原試算表。若 `setup()` 回報既有欄名不符，請不要強制覆寫原工作表；應先確認原欄位與目前版本的差異。

## 四、更新現有 GitHub 與 Apps Script 的步驟

1. **先備份**：複製原 GitHub `index.html`、原 Apps Script `Code.gs`，及整份 Google Sheets。
2. 開啟原 Google Sheets →「擴充功能」→「Apps Script」，**用壓縮檔內新版 `Code.gs` 取代原程式碼**，儲存。
3. 在 Apps Script 函式選單選 `setup` 並執行。回到試算表，確認 `RA_區塊三` 的第 1 列已有 16 個欄位，舊資料仍存在。
4. 在 Apps Script 的「部署 → 管理部署作業」找到目前網站正在使用的部署，選「編輯 → 新版本」，重新部署。僅儲存程式碼並不會讓既有 `/exec` 部署立即使用新版。
5. 用壓縮檔內新版 `index.html` 覆蓋 <https://github.com/madspider02/ra-platform> 儲存庫原本的 `index.html`，提交修改。
6. 如果沿用原本的 Apps Script 部署，通常 `/exec` 網址不變。本檔案的 `API_URL` 已預填上一版使用的網址；**如果你建立了新的 Apps Script 部署，請把 `index.html` 裡的 `API_URL` 改成新的 `/exec` URL。**
7. 等待 GitHub Pages 更新後，再開啟 <https://madspider02.github.io/ra-platform/> 測試。

### 建議測試流程

- 建立一個測試參與者並記下返回代碼；進入區塊 3。
- 在「阿哲」選主責單位、填寫具體措施，對四項原則各選一次並寫理由，完成爭議題後儲存。
- 到「大家的想法」確認主責單位分布及每一欄文字都顯示，再回到「我的填答」修改其中一項判斷並重新儲存，確認沒有新增第二筆人數。
- 切換「德德」與「小紜」，確認兩個案例各自獨立；測試「其他」單位的輸入欄。
- 重整網頁或關閉後再開，確認可以恢復已儲存內容；換裝置時用返回代碼登入，確認已提交的答案也能讀回。
- 檢查第一、二、四區塊仍可正常使用。

## 五、使用和隱私

- 本平台是教學用公開討論頁，參與者選擇的**顯示名稱及文字回答會公開供其他訪客閱讀**。正式活動前應先清楚告知參與者。
- 不要在開放作答欄位填寫真實個案的學生姓名、病歷、診斷或其他可識別資訊；網站範例本身以參考指引的化名案例呈現。
- 同一瀏覽器可暫存**未送出的草稿**，但若換裝置，只有**已成功儲存到 Google Sheets 的資料**可以透過返回代碼取回。
- 不應把 Google Sheets 設為公開編輯。返回代碼僅是方便分次填答的簡易識別碼，並非高安全性的身分驗證；此網站也不是具備嚴格防重複填答、完整資料審核與權限管理的系統。

## 六、修改範圍與測試狀態

更新檔案：`index.html`（第三區塊內容及全體結果呈現）、`Code.gs`（新增第三區塊欄位及讀寫格式）、`README.md`（部署說明）。第一、二、四區塊使用原有功能。

已進行 **JavaScript 語法檢查、Apps Script 模擬測試（含 v2 舊資料相容升級、寫入驗證、重複儲存更新及其他區塊回歸），以及 Chromium 桌面／手機前端互動模擬測試**。但尚未登入你的 Google 帳號或實際部署到線上；正式環境的 Google Sheets 授權、Apps Script 部署與寫入仍需依步驟實測。
