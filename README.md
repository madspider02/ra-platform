# 合理調整宣導討論平台 v2｜GitHub Pages + Google Sheets

網站目標：讓參與工作坊的現職教師，在四個演講區塊中分次思考、填寫，並能即時看到彼此的回應與交流。

## 網址與檔案

- 目前的網站：<https://madspider02.github.io/ra-platform/>
- `index.html`：取代 GitHub 儲存庫根目錄現有的 `index.html`。
- `Code.gs`：**必須**同步取代目前與 Google Sheets 綁定的 Apps Script 原始碼。
- 本版 `index.html` 預填了目前公開網站所用的 Apps Script `/exec` 網址。如果你沿用原本的「部署作業」更新版本，網址通常不必更換；如果是新建部署，則應更新 `API_URL`。

注意：**只更新 GitHub 而未更新 Apps Script，或只更新 Apps Script 而未更新 GitHub，都無法正常使用新版全部功能。**

## 四個討論區塊

| 區塊 | 參與者要做的事 | 全體結果頁 |
|---|---|---|
| 一：宣導重點 | 從「理論、流程、案例、申訴」單選最重要主題，寫出具體宣導內容 | 票數、百分比、每個人的回應；可篩選四主題 |
| 二：學校運作 | 依「提起申請釐清狀況／對話討論確認措施／執行調整追蹤檢討」分三階段，各填「可能發生的問題」及「需要的資源」 | 可切換三階段看所有人的問題與資源 |
| 三：案例推演 | 選擇案例，各填「如何評估及落實調整」與「若有爭議如何處理」 | 可依案例切換，共同觀看回答；另附指引中的處理方式摘要 |
| 四：常見問題 | 提出多個常見問題，逐題回覆其他人的提問 | 問題與回覆串呈現，可撤回自己的提問與回覆 |

第三區塊的案例來自教育部 114 年 8 月《各教育階段學校及幼兒園提供合理調整參考指引》：
- 案例 8：輪椅學生的畢業旅行交通安排（指引印刷頁 17–18）
- 案例 9：學生希望全面更換教室照明設備（印刷頁 18–19）
- 案例 11：學習障礙學生提出使用語音輸入完成作業（印刷頁 20–21）

畫面採用適合課堂的簡潔淺藍系，保留「合理調整宣導討論平台」名稱及製作者署名。

## 首次更新既有網站（請按順序）

**第 0 步：備份**

1. 將原 GitHub 的 `index.html` 另存備份。
2. 將原 Apps Script 的程式碼複製到安全位置。
3. 為目前的 Google Sheets 製作副本，以保存既有填答資料。

**第 1 步：更新 Google Apps Script**

1. 開啟目前存放活動資料的 **Google Sheets**。
2. 進入「擴充功能 → Apps Script」。
3. 將現有 `Code.gs` 內容替換為本壓縮檔內的 `Code.gs`。
4. 儲存。函式選單選擇 `setup`，按下「執行」，依序授予試算表權限。
5. 返回試算表，確認新增或保留以下 **7 張**以 `RA_` 開頭的工作表：
   `RA_參與者`、`RA_區塊一`、`RA_區塊二`、`RA_區塊三`、`RA_區塊四提問`、`RA_區塊四回覆`、`RA_寫入確認`。
6. `setup()` 只會在未存在的工作表上建立標題列，**不會刪除原工作表或原資料**。

**第 2 步：更新原本的網頁應用程式部署**

1. 在 Apps Script 按「部署 → 管理部署作業」。
2. 找到**目前網站正在使用的**網頁應用程式部署，按鉛筆（編輯）。
3. 「版本」選擇「新增版本」（New version），完成更新部署。
4. 確認「執行身分」為 **我**，存取權為 **所有人**（若組織的權限政策允許）。
5. 確認部署的 `/exec` 網址是否與原本相同；若不同，編輯新版 `index.html` 中的 `API_URL`。

> 不能只按「儲存程式碼」；使用中的正式 `/exec` 部署也必須切換至新版。

**第 3 步：更新 GitHub Pages**

1. 開啟 <https://github.com/madspider02/ra-platform>。
2. 進入 `index.html`，以本壓縮檔新版內容取代，提交到 `main` 分支。
3. 若 GitHub Pages 已啟用，等待新的頁面發布即可，網址維持 <https://madspider02.github.io/ra-platform/>。
4. 不要將 `Code.gs`（尤其是試算表設定與回條資料）上傳到可公開編輯的程式位置作為後端；`Code.gs` 要貼入 Google Apps Script。

**第 4 步：測試**

1. 以無痕視窗開啟網站，試填「王老師」或勾選匿名。
2. 建立身分後，確認可以複製 **24 碼返回代碼**。
3. 第一區塊選一個主題填入回答，按儲存，檢查結果頁的票數與回應。
4. 第二區塊儲存其中一個階段，切換另一階段，檢查兩者可以分別儲存與修改。
5. 第三區塊儲存案例的兩道題目，進入共同討論頁檢查。
6. 第四區塊提出問題、發布回覆，檢查回答串。
7. 重開原瀏覽器，應能接續既有身分；或換一台裝置輸入返回代碼恢復。
8. 檢查 Google Sheets 各 `RA_` 工作表是否都有資料。正式活動前可刪除測試資料，但要注意跨工作表的對應關係。

## 你原本已經有的舊資料，如何保留？

- `setup()` **不會清除**之前的試算表資料。
- 新版的「區塊一」預設讀取 `RA_區塊一`，**不會自動顯示舊版回應**，以免重複計票。
- 如果希望把舊版「理論／流程／案例／申訴」填答也顯示在新系統：
  1. 先備份原試算表。
  2. 在 `Code.gs` 的 `importLegacyIntro()` 中修改 `legacyName`，使其等於舊版原始工作表名稱（預設是 `Responses`）。
  3. 舊表標題列至少要有 `topic` 和 `content` 欄（選填 `timestamp`）。
  4. 在 Apps Script 手動執行一次 `importLegacyIntro()`。
  5. 舊資料會複製到 `RA_區塊一`，公開名稱為「舊版匿名回應」，但舊參與者無法透過新版返回代碼編輯它們。
- 匯入採舊表「工作表名稱 + 列號」辨識，重複執行不會重複匯入既有列；如果舊表之後重新排序或插入列，應先檢查再匯入。

## 重返填寫和隱私說明

- 參與者可用真名、暱稱或匿名代碼；**填寫時所顯示的名稱及公開內容會讓其他訪客看見**。
- 同一瀏覽器的 `localStorage` 會保存返回代碼，避免每次重填。換裝置時可輸入原代碼。
- 返回代碼相當於簡易存取憑證，可讀取及修改該參與者的回答，請勿公開分享。如果清除瀏覽器資料且忘記代碼，網頁本身無法自助找回。
- 各區塊分開儲存：第一區塊一人一票、更新不增加票數；第二區塊每人每階段一筆；第三區塊每人每案例一筆；第四區塊允許多筆提問與回覆。
- 正式公開的結果頁可顯示所有參與者的選擇與文字回答；公開結果**不顯示返回代碼**。但此網站不具備強身分驗證，亦無法保證每人只建立一個身分。
- Google Sheets 不應開放為所有人可編輯。此方案適用一般工作坊，**不可蒐集學生姓名、診斷、詳細個案背景或其他敏感資料**。
- 透過 Google Apps Script 的 GET/JSONP 讀取資料；文字寫入改用跨來源 POST，並透過「寫入確認」工作表的回條確認是否成功。返回代碼仍用於讀取自己的填答，因此它是便利恢復功能，**不是高安全性的登入認證**。
- 公開網頁應用程式可能受到惡意灌票或大量回覆。若有不當內容，管理者可在 `RA_區塊四提問`／`RA_區塊四回覆` 的 `status` 欄將 `visible` 改成 `hidden`，即可使該筆公開頁不顯示。對大量公開活動建議使用具備登入、審核與速率限制的完整後端。

## 後續維護

- 每次只要修改 `index.html`，可直接推送 GitHub 更新。
- 只要修改 `Code.gs`，必須在 Apps Script 中儲存、**重新更新部署版本**。
- 若調整案例的文字，請保持所引用的指引案例編號與核心事實一致。
- 回答資料是儲存在 Google Sheets，不在 GitHub repository 中。
- 結果頁每 20 秒重新抓取資料，也提供手動「重新整理」。

> 這一版已對前端互動流程與後端資料邏輯進行本機模擬測試。由於無法替你登入現有 Google 帳號，正式 Apps Script 授權與實際 Google Sheets 寫入仍須在你的環境依照上述流程確認。
